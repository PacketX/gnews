# GRISM DPDK 系列(7.x)版本資訊

arm64 機型:Q16、F3T1G4、T4G12、H2。MIPS 機型的版本資訊在[這裡](release-mips.md)。

## GRISM-7.6.261104.2
\- 新增功能 \-
- 大量過濾清單的即時載入預設開啟(設定 → 封包處理 → 篩選器即時更新),IPv4 CIDR 與 IPv6 清單也改為即時載入,不再整份重新載入;從清單檔拿掉的過濾器隨下一次載入即時移除
- 告警新增「過濾清單未套用」:清單載入失敗時告警,之後載入成功自動解除(設定 → 告警)
- 過濾器與鏈的頁面列出裝置上既有、本設定未定義的過濾器(即時載入的清單等),鏈可直接引用

\- 問題修正 \-
- 改善大型過濾清單載入與更新的穩定性與記憶體用量;放不下時保留使用中的清單,並記錄於系統紀錄
- 修正管理介面重新註冊後,SNMP 中 GRISM 埠的 ifIndex 位移的問題
- 修正 SNMP 查詢耗時過長時 SNMP 子代理程式結束的問題

\- 項目變更 \-
- 系統元件更新:OpenSSL 3.5.9、nginx 1.30.6、Python 3.11.13、OpenSSH 10.6p1,並隨每次韌體更新安裝(之前只在完整安裝時安裝);更新檔較大,更新所需時間較長
- 每台機器改用自己的 SSH 主機金鑰(原本出廠共用同一組):升級後第一次 SSH 連線會提示主機金鑰已改變
- 管理介面不再接受帶有 IP 選項的 TCP 封包,防範 Linux 核心的已知弱點
- SNMP 中 GRISM 埠的 ifIndex 編號在升級後改變一次;需要固定時在 snmpd.conf 設定 grismPortIfIndexBase


## GRISM-7.6.261028.1
\- 新增功能 \-
- 自動化介面:API 權杖、設定的驗證與路徑追蹤、逾時未確認即自動還原的設定提交、裝置能力查詢、事件紀錄與 webhook(設定 → API 權杖 / Webhook)
- 回放輸入可設定速度倍率,以擷取檔原本節奏的倍數播放

\- MEC \-
- 對應表跟隨 UE 上網用的 bearer / PDU session:4G 上網 bearer 不是 E-RAB 5 時也能學到,IMS 與語音 bearer 不再被當成上網;5G 依 5QI 略過 IMS session
- 解析 5G PDU session 修改(PDUSessionResourceModify 與 ModifyIndication):session 的隧道搬移後,分流跟著走新的隧道
- 有多個 PDU session 的 UE 換手(Xn / N2)後,保留上網 session 的隧道與 cell
- 解析 E-RAB 釋放與 PDU session 釋放:上網的 bearer / session 釋放時對應項目一併移除,重新建立時改用新的隧道
- SCTP 分割訊息的重組以連線、stream 與序號區分:不同基地台同時送出相同序號的分割訊息時不再互相干擾
- 改善換手在高負載下的穩定性:換手請求與確認同時到達時不再遺失
- 修正 s1apItemsAllowIp 設為單一位址時封包引擎停止,以及設為 /0 時只符合網路位址的問題
- 以兩個營運網路的實際訊令(各約 3 小時)回放驗證;4G S1 換手驗證通過;T12S-MEC 在每秒約 100 萬個 S1AP 封包下不掉包;10 萬個 session 在持續上行流量下反覆建立與釋放,對應表與索引皆正確回收


## GRISM-7.6.261016.1
\- 新增功能 \-
- 登入驗證可設定「允許本機登入的主機」:TACACS+ / RADIUS 開啟時,列出的位址改用本機帳號登入(設定 → 登入驗證)
- 系統紀錄可檢視較舊的紀錄檔,並可將全部紀錄檔壓縮下載
- 告警新增 MEC 對應表使用率,達 95% 時告警(設定 → 告警)

\- 問題修正 \-
- 修正 regex 篩選器含有引擎不支援的語法時,影響其他篩選器或使封包引擎停止的問題
- 修正清除管理介面閘道器後設定未生效的問題
- 修正設定 bypass filter 時監控程式異常結束的問題
- 修正多核心下流量統計計數偶有少算的問題
- 修正封包緩衝耗盡時封包引擎停止的問題
- 修正埠的 outDrops 計數與來源 IP 設定的問題

\- 項目變更 \-
- 流量統計 API 需登入後才能讀取
- 系統紀錄記錄請求的真實來源位址
- verbose 模式下,系統紀錄可追蹤封包擷取與 ARP 送出的過程(除錯用)

\- MEC \-
- 對應表的三個索引(上行 TEID、UE 位址、AMF/MME UE id)改為可刪除的 bucket 結構:session 釋放、淘汰或閒置清除時索引同步移除,查詢成本不再隨使用率上升;對應表接近滿載時封包處理不再停滯(之前 90% 以上每個封包多花 2.8 µs,接近全滿時降到每秒數百個封包)
- UE 位址與 TEID 索引的大小至少為對應表的兩倍,設定值較小時自動提高
- 對應表節點的 bucket 雜湊改良:AMF 與基地台同步編號的 UE 不再集中在同一個 bucket(之前 1000 個只能留下 100 個)
- cell 與 UE id 的對應加入基地台位址:多個基地台各自從 1 編號時不再互相覆蓋
- 換手(Xn path switch 與 N2 handover)後保留基地台位址與 cell;5G 新增解析 HandoverNotify 與 PathSwitchRequest 的位置資訊;修正 5G path switch 後 cell 為 0 的問題
- 同一 UE 的第二個 bearer / PDU session 的隧道與位址一併保留
- 新增 nrCellIdentityBits 設定:5G 的 cell id 取 NR Cell Identity 的高位元數,預設 26(設定 → MEC)
- 下行 GTP 封裝找不到對應 session 而丟棄時,每分鐘在系統紀錄寫出數量與目的位址
- 開啟 s1apItemsUpdateLog 並設定類型為 mec 的 syslog 目標時,逐筆送出對應表的變動(除錯用)
- 在 900 個 UE、約 400 Mbps、對應表 90% 的環境下,換手、SCTP 分割訊令與大量 session 增減皆驗證通過
