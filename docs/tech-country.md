# 國家統計的規則:哪一端的國家算,怎麼算

「流量統計 › 國家」這一頁(API 是 `get_country_counter`)把流量依國別加總。它的算法從 6.6.261110 / 7.6.261110(引擎 2.11.44 / 2.9.47、Studio 2.269.0)起有兩種:**預設的算法與以前完全相同**;只有在你為埠指定了 WAN/LAN 端,或填了本地網段之後,才改為只計遠端那一端並區分進出。這份文件把兩種算法與其間的判定順序寫清楚。

## 共通的前提

- **以連線為單位**,不是逐封包。一條連線在離開連線表時才計入:閒置逾時(預設 30 秒)、活動逾時(預設 7200 秒)、TCP FIN/RST 後 5 秒,或清除計數器時。所以這一頁比實際流量晚一個逾時時間。
- 連線的兩端位址各查一次 DB-IP 國別資料庫(`dbip-country-YYYY-MM.mmdb`,可在「設定 › 服務」更新),得到兩碼國別,或「查不到」。私有位址、TEST-NET、尚未配發的位址都查不到。
- 一條連線的封包數與位元組是**雙向合計**。連線的**第一個封包**決定「來源 → 目的」的方向,也記下它是從哪個埠進來的。
- 只統計 IPv4。需要連線追蹤(`flow`)開啟、`mmdb_country_counter` 開啟、資料庫載入成功。

## 模式一:both(預設)

什麼都沒設時就是這個模式,與以前的版本完全相同。每條連線:

1. 來源端查得到國家,該國加上整條連線(封包、位元組,連線數 +1)。
2. 目的端查得到國家、且與來源不同國,該國也加上整條連線;同一國只加一次。
3. 查不到國家的那一端什麼都不加;兩端都查不到(例如私有位址對私有位址)的連線完全不計。
4. 沒有進出之分:`in_*` / `out_*` 都是 0,`local` / `unknown` / `undirected` 也都是 0。

後果是跨國的連線會出現在兩個國家,各國總和最多接近實際流量的兩倍;本站自己的公網 IP 也會以其國家列出,通常就是最大的那一列。

## 模式二:remote

只要**任一埠**設了 WAN/LAN 端(埠的 `side` 為 `wan` 或 `lan`),或 `countryLocalNetworks` 有值,就進入這個模式。每條連線依序判定:

1. 先判定兩端是否「本地」:位址落在 `countryLocalNetworks` 列的網段內,或是私有位址(10/8、172.16/12、192.168/16、100.64/10、169.254/16、127/8),就是本地。
2. 兩端都本地:整條連線歸 **local**(本地對本地),不計任何國家。
3. 只有一端本地:另一端就是遠端。
4. 兩端都不是本地:看第一個封包**進入埠**的 side。`wan` 表示來源是遠端(連線由遠端發起);`lan` 表示目的是遠端(連線由本地發起)。
5. 判出遠端之後,遠端查得到國家,**只有該國**加上整條連線,並拆出方向:`in_*` 是遠端送往本地的流量,`out_*` 是本地送往遠端的流量;遠端發起的連線算 `in_flows`,本地發起的算 `out_flows`。遠端查不到國家,整條連線歸 **unknown**(國別不明)。
6. 判不出來的連線(兩端都是公網、都不在清單內、進入埠沒有 side)歸 **undirected**(無法判定內外),並且**照 both 模式計入兩端的國家**。這一列有數字,就表示還有埠或網段沒設定。

兩點容易混淆:

- `in` / `out` 是**流量方向**,`in_flows` / `out_flows` 是**誰發起**。本地使用者下載一個檔案,是 `out_flows` 加 1、`in_bytes` 很大。
- 清單優先於埠的 side;私有位址不管從哪個埠進來都是本地。

### LAN 端有公網 IP 怎麼辦

如果 WAN 埠和 LAN 埠都設了 side,其實不需要清單。本地的公網主機往外連,第一個封包從 LAN 埠進來,來源就是本地;外面連進來,第一個封包從 WAN 埠進來,來源是遠端。清單是給埠分不出內外的情況用的,最常見的是 SPAN 把雙向流量鏡射到同一個埠,或只接了其中一邊。

## 例子

驗證時用的五條連線(DB-IP 2025-10 的判定:8.8.8.8 與 8.8.4.4 是美國、168.95.1.1 是台灣、1.1.1.1 是澳洲、31.13.87.52 是台灣、203.0.113.5 查不到),在四種設定下的結果:

| 連線(第一個封包的方向) | both | 進入埠 side=wan | 進入埠 side=lan | 清單 203.0.113.0/24,無 side |
|---|---|---|---|---|
| 192.168.50.10 → 8.8.8.8 | US | US,本地發起 | US,本地發起 | US,本地發起 |
| 168.95.1.1 → 1.1.1.1 | TW 與 AU 各一次 | TW,遠端發起 | AU,本地發起 | undirected,TW 與 AU 各一次 |
| 203.0.113.5 → 8.8.4.4 | US | unknown | US,本地發起 | US,本地發起 |
| 10.0.0.1 → 10.0.0.2 | 不計 | local | local | local |
| 31.13.87.52 → 192.168.50.11 | TW | TW,遠端發起 | TW,遠端發起 | TW,遠端發起 |

G8S-MEC 與 Q16 兩台機器、四種設定的實測結果都與這張表一致。

## 怎麼設定

- **埠的 WAN/LAN 端**:「設定 › 介面」每個埠多了一欄,選 WAN、LAN 或未指定。只有變更過的埠會送出;改 side 會重新載入引擎設定,流量中斷數秒。API 寫法:
  ```xml
  <configSet reboot="no">
    <interfaces><ports><find name="P0"><side>wan</side></find></ports></interfaces>
    <interfaces><ports><find name="P1"><side>lan</side></find></ports></interfaces>
  </configSet>
  ```
  `<side></side>` 表示取消。
- **本地網段**:「設定 › 封包處理 › 連線追蹤」卡片的「本地網段」欄位,填 IPv4 位址或網段,以空白、逗號或分號分隔;寫錯的項目會被略過。API:
  ```xml
  <configSet reboot="no"><args><countryLocalNetworks>203.0.113.0/24, 198.51.100.7</countryLocalNetworks></args></configSet>
  ```
  空元素表示清除。
- 兩項設定都會出現在「原始設定」的 XML(`get_config_xml`),也會隨韌體更新帶過去。

## 回傳的 JSON

`country_counter[]` 每筆一直都有的三個欄位 `iso_code`、`packets`、`bytes`,在兩種模式下的意義都是「該國出現過的每條連線的雙向合計」,舊程式照讀。新的欄位加在旁邊:

| 欄位 | 意義 |
|---|---|
| `flows` | 計入該國的連線數 |
| `in_packets` / `in_bytes` | 遠端送往本地的流量(remote 模式才有值) |
| `out_packets` / `out_bytes` | 本地送往遠端的流量 |
| `in_flows` / `out_flows` | 由遠端 / 本地發起的連線數 |
| 頂層 `mode` | `both` 或 `remote` |
| 頂層 `local` / `unknown` / `undirected` | 各 `{packets, bytes, flows}`,意義如上 |

Studio 的國家頁會寫出目前是哪一種模式;remote 模式多了進向、出向與「連線數 進 / 出」欄,「本地對本地」不為 0 時列在各國之後。`unknown` 與 `undirected` 只在 JSON 裡,頁面不列,以免讀的人誤會。

## 不受模式影響的部分

- `country.iso_code` 過濾器維持原樣:來源或目的任一端是該國就命中,本站自己的公網位址也算。
- IPv6 連線不計國別。
- 改 side 或清單會重新載入引擎設定,計數器隨之歸零;「清除計數器」也會歸零。國家頁自己的「清除」(API `clear_country_counter`,操作等級)只歸零國家統計,埠、篩選器與連線的計數都不動。
