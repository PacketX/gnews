# regex 篩選器:兩條產品線對 PCRE 語法的支援

## 兩個不同的引擎

`<find name="regex">` 在兩條產品線上是兩套完全不同的實作,同一條規則不保證有同樣的結果:

| | arm64(DPDK)機種,7.6.x | MIPS 機種,6.6.x |
|---|---|---|
| 引擎 | PCRE2 10.42(軟體) | Cavium HFA(硬體加速) |
| 規則怎麼進引擎 | 每條規則各自編譯 | 整份設定的所有 regex 一行一條,合編成**一張** graph |
| 編譯器 | 引擎內建 | CN73/78(T12S、T20 系列)用 Gen4;其餘(G8S、G8、G4…)用 Gen3 |
| 預設行為 | 區分大小寫;`.` 不含換行;`^` `$` 是 payload 的頭尾 | 區分大小寫;`.` 不含換行;`^` `$` **在每個換行處也成立** |

兩邊都是**以位元組比對**(沒有 UTF-8 模式),預設比對 L7 payload,每個封包各自比對、不跨封包。

```xml
<filter id="10" name="sql">
  <or>
    <find name="regex" relation="==" content="(?i)union\s+select" />
  </or>
</filter>
```

## 測試方法

準備 137 條規則,分 14 類(字面、跳脫、錨點、量詞、字元類別、POSIX 類別、簡寫、反向參照、群組、斷言、行內選項、Cavium 擴充、實際常見規則…),每條規則配 1~5 個 payload,其中有該符合的,也有不該符合的。每一組(規則、payload)都實際從設備的 loopback 埠重播一次,由篩選器計數器讀出設備的判斷,再與 **PCRE2 10.42 函式庫本身**對同一組資料的答案逐一比對。

| | 結果 |
|---|---|
| arm64(HL1) | PCRE2 接受的 135 條,每個 payload 的結果都與 PCRE2 完全一致 |
| MIPS Gen4(T12S) | 編譯器接受 126 條;其中可與 PCRE2 對照的 123 條,107 條完全一致,16 條不同(見下) |
| MIPS Gen3 | 只驗證了編譯器:接受的語法與 Gen4 相同,只少一項 `**` |

137 條中有 2 條本來就不是 PCRE 語法(`\x{4142}` 與 `**`),PCRE2 自己不接受。

## 語法支援對照

✔ = 接受,且結果與 PCRE2 相同。

| 語法 | arm64 | MIPS |
|---|---|---|
| 字面字元、`\.` 這類跳脫 | ✔ | ✔ |
| `\xhh` `\x{hh}` `\ddd`(八進位)`\t` `\r` `\n` `\a` `\e` `\f` `\cA` `\Q…\E`;NUL 與 0x80 以上的位元組 | ✔ | ✔ |
| `.`、`a\|b`、群組 `( )`、不擷取群組 `(?:…)` | ✔ | ✔ |
| `*` `+` `?` `{n}` `{m,n}` `{m,}`,以及 lazy 形式 `*?` `+?` `??` `{m,n}?` | ✔ | ✔ |
| 字元類別 `[abc]` `[^abc]` `[a-f0-9]` `[\x00-\x1f]` `[\d\s]` | ✔ | ✔ |
| POSIX 類別 `[[:alnum:]]` … `[[:xdigit:]]`(14 個全部),含否定 `[[:^digit:]]` | ✔ | ✔ |
| `\d` `\D` `\w` `\W` `\S` `\h` `\H` | ✔ | ✔ |
| 反向參照 `\1` `\g1` `\g{1}` `\g{-1}`;具名群組 `(?<n>…)` `(?'n'…)` 與 `\k<n>` `\k'n'` `\k{n}` | ✔ | ✔ |
| `\b` `\B` `\A` `\z` `\Z` | ✔ | ✔ |
| lookaround `(?=…)` `(?!…)` `(?<=…)` `(?<!…)` | ✔ | ✔ |
| 行內選項 `(?i)` `(?i:…)` `(?-i)` `(?s)` `(?m)` `(?x)`,註解 `(?#…)` | ✔ | ✔ |
| `^` `$` | payload 的頭尾 | **不同**:每個換行處也成立 |
| possessive 量詞 `*+` `++` `?+` `{m,n}+` | ✔ | **不同**:接受,但行為等同一般(greedy)量詞 |
| `\v` `\s` `\V` | ✔ | **不同**:`\v` 只代表 VT(0x0B)一個字元,所以 `\s` 不含 VT、`\V` 會符合換行 |
| `\N` `\o{…}` `\G` | ✔ | **不同**:接受,但永遠不符合 |
| `\K` | ✔ | 接受但被忽略(不影響是否符合) |
| Python 式具名群組 `(?P<n>…)` `(?P=n)` | ✔ | ✘ |
| atomic 群組 `(?>…)`、branch reset `(?\|…)`、條件式 `(?(1)…)`、遞迴與子程式呼叫 `(?1)` | ✔ | ✘ |
| `(?U)`、`(*…)` 起始指令、callout `(?C)` | ✔ | ✘ |
| `\R`、Unicode 屬性 `\p{…}` | ✔ | ✘ |
| Cavium 巨集 `{i}` `{s}` `{x}` `{t}` `{@n}`(見下) | 當成字面文字 | ✔ |
| 多位元組十六進位 `\x{4142}` | ✘ | ✔ |
| `**` | ✘ | Gen4 ✔,Gen3 ✘ |

HFA 的語法文件與實測有三處不同(Gen4):文件說 `^` 會被換成 `\n`,實際上 payload 開頭也符合;文件說 `\h` 含換行,實際不含,與 PCRE 相同;`(?:…)` 文件沒列,實際可用。

## 接受但結果不同的例子

這幾類最容易出錯,因為兩邊都不會報錯,只是答案不一樣:

| 規則 | payload | arm64 | MIPS |
|---|---|---|---|
| `^abc` | `zz⏎abcdef` | 不符合 | 符合 |
| `abc$` | `abc⏎zz` | 不符合 | 符合 |
| `^abc$` | `x⏎abc⏎y` | 不符合 | 符合 |
| `xa++ay` | `xaaay` | 不符合 | 符合 |
| `x\sy` | `x`、VT、`y` | 符合 | 不符合 |
| `x\vy` | `x⏎y` | 符合 | 不符合 |
| `x\Vy` | `x⏎y` | 不符合 | 符合 |
| `a\Nb` | `axb` | 符合 | 不符合 |
| `x\o{101}y` | `xAy` | 符合 | 不符合 |
| `\Gabc` | `abcx` | 符合 | 不符合 |

(⏎ 代表換行 0x0A。)

## Cavium 巨集(只有 MIPS)

HFA 的規則可以在最前面加一段 `{…}`,多個屬性用逗號分開,例如 `{i,s}a.c`:

| 巨集 | 作用 | 兩邊都能用的寫法 |
|---|---|---|
| `{i}` | 不分大小寫 | `(?i)` |
| `{s}` | `.` 也符合換行 | `(?s)` |
| `{x}` | 忽略規則中的空白 | `(?x)` |
| `{@n}` | 只在距開頭 n 個位元組處符合;`{@0}` 即開頭 | 開頭可用 `\A` |
| `{t}` | 回報符合的起始位置(不影響是否符合) | — |

arm64 上這段**不是巨集而是字面文字**:`{i}hello` 在 MIPS 是不分大小寫的 hello,在 arm64 則是要符合 `{i}hello` 這八個字元。兩邊都不會報錯。

另外,MIPS 上以 `#` 開頭的規則會被編譯器當成註解;要比對 `#` 開頭的內容請寫 `[#]` 或 `\x23`。

## 寫出兩邊結果一致的規則

- 只用對照表前半「兩邊都 ✔」的語法;實際常見的規則(e-mail、IPv4、HTTP 請求列、Host 標頭、卡號、URL、十六進位雜湊、`(?i)union\s+select`、檔案 magic)在兩邊結果都相同。
- 選項用 `(?i)` `(?s)` `(?x)`,不要用 `{i}` 這類巨集。
- 要錨定 payload 的頭尾用 `\A` 與 `\z`;要逐行錨定就明寫 `(?m)^`、`(?m)$`。單獨的 `^` `$` 在 payload 含換行時兩邊答案不同。
- 不要用 possessive 量詞與 atomic 群組來「防止回溯」:MIPS 不支援或不照做。
- 空白字元要包含 VT 時寫 `[ \t\r\n\f\x0b]`;任意換行寫 `(?:\r\n|\n|\r)` 代替 `\R`;非換行寫 `[^\n]` 代替 `\N`。
- 具名群組寫 `(?<n>…)`,不要寫 `(?P<n>…)`。
- 兩邊都以位元組比對:非 ASCII 內容用 `\xhh` 逐位元組寫,不要用 `\p{…}`。

## 引擎不接受的規則

含有引擎不接受的 regex 的篩選器,**只有它自己失效**:這個篩選器什麼都不符合(用 `F`、`!F`、`!=`、放在 `<or>` 裡都一樣),其他篩選器與鏈結照常載入。記錄檔會指出是哪個篩選器、哪條規則、引擎給的原因,篩選器計數器上會看到它有嘗試、但符合數一直是 0(下面第一行是 MIPS,第二行是 arm64):

```
[ERROR] filter 7002: regex "x(?>a+)ay" is not accepted by the HFA compiler (unexpected char after (?), so the filter matches nothing
[ERROR] filter 7002: regex "ab**c" is not accepted by PCRE2 (quantifier does not follow a repeatable item, at offset 3), so the filter matches nothing
```

讓它「什麼都不符合」而不是「少一個條件照常運作」,是因為少了條件的篩選器意思已經和原本寫的不同;如果只剩空的篩選器,更會變成符合所有封包。

**6.6.261008.4 / 7.6.261008.1 以及更早的版本沒有這層保護**,一條不被接受的規則會影響整份設定:arm64 上排在它後面的篩選器與鏈結不會載入;MIPS 上因為所有規則合編成一張 graph,整張都編不出來,regex 比對無法運作,並可能使封包引擎停止。在這些版本上請先確認每一條規則都在支援範圍內再套用。

要事先確認一條規則:

- **arm64**:用任何 PCRE2 工具(`pcre2test`,或線上測試器選 PCRE2),不加任何旗標。
- **MIPS**:在設備上用它自己的編譯器單獨編這一條,不會動到正在運作的設定;`-target` 用 `GRISM.config.json` 裡 `args.hfaTarget` 的值。沒有產生 `/tmp/g` 就是不接受,原因印在畫面上。

  ```bash
  printf '%s\r\n' '要檢查的規則' > /tmp/p
  /usr/local/hfa/hfacg4 -target cn73xx -input /tmp/p -out /tmp/g -rc -force                # Gen4:T12S(cn73xx)、T20 系列(cn78xx)
  /usr/local/hfa/hfac   -target cn70xx -input /tmp/p -out /tmp/g -warn /tmp/w -rc -force   # Gen3:G8S、G8、G4(cn70xx)
  ```
