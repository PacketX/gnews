# regex 篩選器:兩條產品線對 PCRE 語法的支援

## 兩個不同的引擎

`<find name="regex">` 在兩條產品線上是兩套完全不同的實作,MIPS 這邊又分兩代編譯器,同一條規則不保證有同樣的結果:

| | arm64(DPDK)機種,7.6.x | MIPS 機種,6.6.x |
|---|---|---|
| 引擎 | PCRE2 10.42(軟體) | Cavium HFA(硬體加速) |
| 規則怎麼進引擎 | 每條規則各自編譯 | 整份設定的所有 regex 一行一條,合編成**一張** graph |
| 編譯器 | 引擎內建 | **Gen4**:CN73/78(T12S、T20 系列);**Gen3**:其餘(G8S、G8、G4…) |
| 預設行為 | 區分大小寫;`.` 不含換行;`^` `$` 是 payload 的頭尾 | 區分大小寫;`.` 不含換行;`^` `$` 的意思與 PCRE 不同,兩代也不同(見下) |

三者都是**以位元組比對**(沒有 UTF-8 模式),預設比對 L7 payload,每個封包各自比對、不跨封包。

```xml
<filter id="10" name="sql">
  <or>
    <find name="regex" relation="==" content="(?i)union\s+select" />
  </or>
</filter>
```

## 測試方法

準備 137 條規則,分 14 類(字面、跳脫、錨點、量詞、字元類別、POSIX 類別、簡寫、反向參照、群組、斷言、行內選項、Cavium 擴充、實際常見規則…),每條規則配 1~5 個 payload,其中有該符合的,也有不該符合的。每一組(規則、payload)都實際從設備的 loopback 埠重播一次,由篩選器計數器讀出設備的判斷,再與 **PCRE2 10.42 函式庫本身**對同一組資料的答案逐一比對。

| | 編譯器接受 | 可與 PCRE2 對照 | 結果相同 | 結果不同 |
|---|---|---|---|---|
| arm64(HL1) | 135 | 135 | 135 | 0 |
| MIPS Gen4(T12S) | 126 | 123 | 107 | 16 |
| MIPS Gen3(G8) | 125 | 123 | 98 | 25 |

137 條中有 2 條本來就不是 PCRE 語法(`\x{4142}` 與 `**`),PCRE2 自己不接受。「結果不同」裡各有 6 條是 Cavium 巨集,在 PCRE 本來就是另一個意思;Gen3 的 25 條裡另有 3 條單獨使用時是正確的,是被同一批的其他規則影響(見「Gen3:相似的規則會互相影響」)。

## 語法支援對照

✔ = 接受,且結果與 PCRE2 相同。

| 語法 | arm64 | MIPS Gen4 | MIPS Gen3 |
|---|---|---|---|
| 字面字元、`\.` 這類跳脫 | ✔ | ✔ | ✔ |
| `\xhh` `\x{hh}` `\ddd`(八進位)`\t` `\r` `\n` `\a` `\e` `\f` `\cA` `\Q…\E`;NUL 與 0x80 以上的位元組 | ✔ | ✔ | ✔ |
| `.`、`a\|b`、群組 `( )`、不擷取群組 `(?:…)` | ✔ | ✔ | ✔ |
| `*` `+` `?` `{n}` `{m,n}` `{m,}`,以及 lazy 形式 `*?` `+?` `??` `{m,n}?` | ✔ | ✔ | ✔ ※ |
| 字元類別 `[abc]` `[^abc]` `[a-f0-9]` `[\x00-\x1f]` `[\d\s]` | ✔ | ✔ | ✔ ※ |
| POSIX 類別 `[[:alnum:]]` … `[[:xdigit:]]`(14 個全部),含否定 `[[:^digit:]]` | ✔ | ✔ | ✔ ※ |
| `\d` `\D` `\w` `\W` `\S` | ✔ | ✔ | ✔ |
| `\h` `\H` | ✔ | ✔ | **不同**:`\h` 含換行,`\H` 不含 |
| 反向參照 `\1` `\g1` `\g{1}` `\g{-1}`;具名群組 `(?<n>…)` `(?'n'…)` 與 `\k<n>` `\k'n'` `\k{n}` | ✔ | ✔ | ✔ |
| `\b` `\B` | ✔ | ✔ | ✔(例外:`\b` 配上帶量詞的擷取群組,見下) |
| `\A` `\z` `\Z` | ✔ | ✔ | **不同**:接受但被忽略,等於沒寫 |
| lookaround `(?=…)` `(?!…)` `(?<=…)` `(?<!…)` | ✔ | ✔ | ✔ |
| 行內選項 `(?i)` `(?i:…)` `(?-i)` `(?s)` `(?x)`,註解 `(?#…)` | ✔ | ✔ | ✔ |
| `^` `$` | payload 的頭尾;加 `(?m)` 才含每個換行處 | **不同**:payload 的頭尾**與**每個換行處,等於永遠有 `(?m)` | **不同**:**只有**換行處,`^` 是換行之後、`$` 是換行之前;payload 的開頭與結尾反而不算,加 `(?m)` 也一樣 |
| possessive 量詞 `*+` `++` `?+` `{m,n}+` | ✔ | **不同**:接受,但行為等同一般(greedy)量詞 | 同 Gen4 |
| `\v` `\s` `\V` | ✔ | **不同**:`\v` 只代表 VT(0x0B)一個字元,所以 `\s` 不含 VT、`\V` 會符合換行 | 同 Gen4 |
| `\N` `\o{…}` | ✔ | **不同**:接受,但永遠不符合 | 同 Gen4 |
| `\G` | ✔ | **不同**:接受,但永遠不符合 | **不同**:接受但被忽略,等於沒寫 |
| `\K` | ✔ | 接受但被忽略(不影響是否符合) | 同 Gen4 |
| Python 式具名群組 `(?P<n>…)` `(?P=n)` | ✔ | ✘ | ✘ |
| atomic 群組 `(?>…)`、branch reset `(?\|…)`、條件式 `(?(1)…)`、遞迴與子程式呼叫 `(?1)` | ✔ | ✘ | ✘ |
| `(?U)`、`(*…)` 起始指令、callout `(?C)` | ✔ | ✘ | ✘ |
| `\R`、Unicode 屬性 `\p{…}` | ✔ | ✘ | ✘ |
| Cavium 巨集 `{i}` `{s}` `{x}` `{t}` `{@n}`(見下) | 當成字面文字 | ✔ | ✔ |
| 多位元組十六進位 `\x{4142}` | ✘ | ✔ | ✔ |
| `**` | ✘ | ✔ | ✘ |

※ 單獨使用時正確;與相似的規則一起載入時可能誤判,見「Gen3:相似的規則會互相影響」。

HFA 的語法文件描述的是 Gen3 的行為;Gen4 實測有三處與文件不同:文件說 `^` 會被換成 `\n`,實際上 payload 開頭也符合;文件說 `\h` 含換行,實際不含;`(?:…)` 文件沒列,實際可用。

## 接受但結果不同的例子

這幾類最容易出錯,因為三邊都不會報錯,只是答案不一樣:

| 規則 | payload | arm64 | Gen4 | Gen3 |
|---|---|---|---|---|
| `^abc` | `abcdef` | 符合 | 符合 | **不符合** |
| `^abc` | `zz⏎abcdef` | 不符合 | **符合** | **符合** |
| `abc$` | `zzabc` | 符合 | 符合 | **不符合** |
| `abc$` | `abc⏎zz` | 不符合 | **符合** | **符合** |
| `\Aabc` | `zzabcdef` | 不符合 | 不符合 | **符合** |
| `abc\z` | `abczz` | 不符合 | 不符合 | **符合** |
| `\Gabc` | `abcx` | 符合 | **不符合** | 符合 |
| `\Gabc` | `xabc` | 不符合 | 不符合 | **符合** |
| `xa++ay` | `xaaay` | 不符合 | **符合** | **符合** |
| `x\sy` | `x`、VT、`y` | 符合 | **不符合** | **不符合** |
| `x\vy` | `x⏎y` | 符合 | **不符合** | **不符合** |
| `x\Vy` | `x⏎y` | 不符合 | **符合** | **符合** |
| `x\hy` | `x⏎y` | 不符合 | 不符合 | **符合** |
| `a\Nb` | `axb` | 符合 | **不符合** | **不符合** |
| `x\o{101}y` | `xAy` | 符合 | **不符合** | **不符合** |
| `\b(\d{1,3}\.){3}\d{1,3}\b` | `src=10.20.30.40;` | 符合 | 符合 | **不符合** |

(⏎ 代表換行 0x0A;粗體是與 PCRE2 不同的答案。)

最後一列是 Gen3 上 `\b` 配「帶量詞的擷取群組」的問題:拿掉 `\b`,或把群組改成不擷取的 `(?:\d{1,3}\.){3}`,就與另外兩邊相同。

## Gen3:相似的規則會互相影響

Gen3 機種(G8S、G8、G4)上,兩條規則如果頭尾相同、只差中間重複的部分,**同時載入時**,其中一條可能替另一條回報符合。單獨載入任何一條都正確;arm64 與 Gen4 用同樣的規則組合測過,沒有這個現象。

| 同時載入的兩條規則 | payload | 應該符合的 | Gen3 回報符合的 |
|---|---|---|---|
| `x[a-z]+y`、`x[0-9]+y` | `xabcy` | 只有第一條 | 兩條 |
| `a.*c`、`a.+c` | `ac` | 只有第一條 | 兩條 |
| `a.*?c`、`a.+?c` | `ac` | 只有第一條 | 兩條 |
| `x[a-z]{1,200}y`、`x[a-f0-9]+y` | `xdeagy` | 只有第一條 | 兩條 |

同一輪測試裡沒有出現這個現象的組合:固定次數(`x[a-z]{3}y` 與 `x[a-f]{3}y`)、共同字首的字面字串(`hello1` 與 `hello2`)、一個類別包含另一個(`x[a-z]+y` 與 `x[a-f]+y`)。

在 Gen3 機種上,如果設定裡有這種「頭尾相同、中間是 `+` `*` 重複」的規則組,請用實際的 payload 確認每一條的結果,或把它們合併成一條規則。

## Cavium 巨集(只有 MIPS)

HFA 的規則可以在最前面加一段 `{…}`,多個屬性用逗號分開,例如 `{i,s}a.c`:

| 巨集 | 作用 | PCRE 的寫法 |
|---|---|---|
| `{i}` | 不分大小寫 | `(?i)`(三邊都能用) |
| `{s}` | `.` 也符合換行 | `(?s)`(三邊都能用) |
| `{x}` | 忽略規則中的空白 | `(?x)`(三邊都能用) |
| `{@n}` | 只在距開頭 n 個位元組處符合;`{@0}` 即開頭 | 開頭是 `\A`(Gen3 不認) |
| `{t}` | 回報符合的起始位置(不影響是否符合) | — |

arm64 上這段**不是巨集而是字面文字**:`{i}hello` 在 MIPS 是不分大小寫的 hello,在 arm64 則是要符合 `{i}hello` 這八個字元。兩邊都不會報錯。

另外,MIPS 上以 `#` 開頭的規則會被編譯器當成註解;要比對 `#` 開頭的內容請寫 `[#]` 或 `\x23`。

## 寫出三邊結果一致的規則

- 只用對照表裡三欄都是 ✔ 的語法;實際常見的規則(e-mail、IPv4、HTTP 請求列、Host 標頭、卡號、URL、十六進位雜湊、`(?i)union\s+select`、檔案 magic)在三邊結果都相同。
- 選項用 `(?i)` `(?s)` `(?x)`,不要用 `{i}` 這類巨集。
- **錨定沒有三邊共通的寫法。** payload 的開頭:arm64 與 Gen4 用 `\A`,Gen3 只能用巨集 `{@0}`。payload 的結尾:arm64 與 Gen4 用 `\z`,Gen3 沒有對應寫法。需要錨定頭尾的規則請依機種分開寫。
- 要表達「行首」「行尾」,直接把換行寫進規則,例如 `\nHost: ` 與 `\r\n`,三邊結果相同;單獨的 `^` `$` 三邊是三種意思。
- 不要用 possessive 量詞與 atomic 群組來「防止回溯」:MIPS 不支援或不照做。
- 空白字元請明寫:含 VT 時寫 `[ \t\r\n\f\x0b]`,水平空白寫 `[ \t]` 代替 `\h`;任意換行寫 `(?:\r\n|\n|\r)` 代替 `\R`;非換行寫 `[^\n]` 代替 `\N`。
- 群組不需要反向參照時一律寫成 `(?:…)`;具名群組寫 `(?<n>…)`,不要寫 `(?P<n>…)`。
- 三邊都以位元組比對:非 ASCII 內容用 `\xhh` 逐位元組寫,不要用 `\p{…}`。

## 引擎不接受的規則

含有引擎不接受的 regex 的篩選器,**只有它自己失效**:這個篩選器什麼都不符合(用 `F`、`!F`、`!=`、放在 `<or>` 裡都一樣),其他篩選器與鏈結照常載入。記錄檔會指出是哪個篩選器、哪條規則、引擎給的原因,篩選器計數器上會看到它有嘗試、但符合數一直是 0(下面第一行是 MIPS,第二行是 arm64):

```
[ERROR] filter 7002: regex "x(?>a+)ay" is not accepted by the HFA compiler (unexpected char after (?), so the filter matches nothing
[ERROR] filter 7002: regex "ab**c" is not accepted by PCRE2 (quantifier does not follow a repeatable item, at offset 3), so the filter matches nothing
```

讓它「什麼都不符合」而不是「少一個條件照常運作」,是因為少了條件的篩選器意思已經和原本寫的不同;如果只剩空的篩選器,更會變成符合所有封包。

**6.6.261008.4 / 7.6.261008.1 以及更早的版本沒有這層保護**,一條不被接受的規則會影響整份設定:arm64 上排在它後面的篩選器與鏈結不會載入;MIPS 上因為所有規則合編成一張 graph,整張都編不出來,regex 比對無法運作,並可能使封包引擎停止。在這些版本上請先確認每一條規則都在支援範圍內再套用。

要事先確認一條規則:

- **arm64**:用任何 PCRE2 工具(`pcre2test`,或線上測試器選 PCRE2),不加任何旗標。
- **MIPS**:在設備上用它自己的編譯器單獨編這一條,不會動到正在運作的設定;`-target` 用 `GRISM.config.json` 裡 `args.hfaTarget` 的值。沒有產生 `/tmp/g` 就是不接受,原因印在畫面上。編得過只代表語法被接受,結果是否與 PCRE 相同仍要看上面的對照表。

  ```bash
  printf '%s\r\n' '要檢查的規則' > /tmp/p
  /usr/local/hfa/hfacg4 -target cn73xx -input /tmp/p -out /tmp/g -rc -force                # Gen4:T12S(cn73xx)、T20 系列(cn78xx)
  /usr/local/hfa/hfac   -target cn70xx -input /tmp/p -out /tmp/g -warn /tmp/w -rc -force   # Gen3:G8S、G8、G4(cn70xx)
  ```
